# 0045 — Text from a photo (on-device OCR)

## Context

v0.5 İP3 (plan "İP3 Fotoğraftan metin", appendix A.4, acceptance criterion 4): a photo of a book
page turns into text offline in about 3 seconds on the phone, with at least 95 % of the words
right on 10 test photos. The user picks the lines to keep, fixes misread words and sends the
text to the reader or to word extraction. The web version may be slower. The photo must never
leave the device.

## Decision

1. **Route and flow.** A new row "Fotoğraftan metin" in the Add sheet opens `/fotograf`: pick
   (camera or gallery) → reading (spinner; on the web a progress bar) → review → "Okuyucuda aç"
   (`saveText({ kind: 'ocr' })`, then `readerPath(id)`) or "Kelimeleri çıkar" (`/share?text=…`,
   the existing extraction preview, which shows the usual AI privacy note and sign-in gate).
2. **Camera and gallery are plain `<input type="file" accept="image/*">`** (one with
   `capture="environment"`). In the Android app Capacitor's `BridgeWebChromeClient` answers
   `capture` with the system camera through the app's existing FileProvider; because the
   manifest declares no `CAMERA` permission, Android asks for none. The gallery input opens the
   system picker. On a desktop browser only "Galeriden seç" is shown.
3. **Image preparation** (`src/features/ocr/image.ts`): `createImageBitmap` (applies EXIF
   rotation) → canvas, longest side ≤ 2400 px (`MAX_IMAGE_SIDE`, plenty for book print and
   keeps the 3 s budget), white behind transparency.
4. **Android: a thin app-local plugin** `EngappTextRecognizer`
   (`android/app/src/main/java/.../TextRecognizerPlugin.java`, registered in `MainActivity`
   like `ShareTargetPlugin`) on `com.google.mlkit:text-recognition:16.0.1` — Text Recognition
   v2, **Latin only, model bundled** in the APK (works offline from the first use; no Play
   services download). It takes the prepared JPEG as base64, decodes it off the main thread and
   returns blocks → lines with boxes and the line confidence (0..1).
5. **Web: tesseract.js 7.0.0** (Apache-2.0), loaded with `import()` only after the user picked a
   photo on the web, LSTM engine only, **English model only** (`eng`, tessdata_best integerised,
   2.9 MB). Its worker, wasm core (three SIMD variants; the browser downloads one, ~3.9 MB) and
   model are copied from `node_modules` into `dist/ocr/<tesseract.js version>/` by a small Vite
   plugin (`engapp-ocr-assets`, also serves them in dev). No CDN: nothing is fetched from a
   third party and the photo is read in a Web Worker. The files are not precached (they would
   add ~7 MB to every visit); the service worker caches them on first use (`engapp-ocr`,
   CacheFirst, versioned path), so later photos work offline. The progress bar shows the
   download and the recognition; the page says that the web is slower.
6. **Review screen** (`OcrReview.tsx`): each line is a toggle (tap = out of the text / back in,
   `aria-pressed`) with a pencil to edit it. Page numbers and specks start unticked. Lines below
   confidence 0.6 carry "Emin değil"; if the character-weighted page confidence is below 0.75
   a warning asks the user to compare with the photo, which can be opened on the same screen.
   Fewer than 12 letters → "Fotoğrafta metin bulunamadı".
7. **Text rebuild is a pure domain function** (`src/domain/ocr.ts`, unit + property tests):
   ligatures spelled out; lines of a paragraph joined with a space; a word hyphenated at a line
   end joined ("exam-" + "ple" → "example"), except common compound prefixes ("self-aware",
   "well-known"), a capital or digit after the hyphen, or an optional word check (`isWord`);
   paragraphs from geometry: a step down clearly larger than the block's own median line pitch,
   a first-line indent, or a short line ending a sentence; every engine block is a paragraph
   unless it continues the previous sentence (no sentence end + lowercase start). Paragraphs are
   separated by a blank line, the `ReaderText.body` convention.
8. **Privacy.** The photo is never uploaded or stored; only the text the user saves is kept,
   locally, as a `texts` row (user-private, rule 5). `/gizlilik` (TR and EN) and
   `docs/play-store/data-safety.md` disclose that the ML Kit SDK sends usage and performance
   metrics (device/OS/app version, a per-installation id, latency, error codes, no image or
   text) to Google; Data safety gains Diagnostics / Other performance data (Analytics) and the
   ML Kit id under Device or other IDs. `PRIVACY_UPDATED` is 2026-10-26.

## Why (and deviations from the plan)

- **No `@capacitor-mlkit/text-recognition`.** Its licence is fine (Apache-2.0, not an Insiders
  package; checked in the 8.2.1 tarball), but it declares the Chinese, Devanagari, Japanese and
  Korean models as hard dependencies next to Latin — tens of MB of bundled models we never use.
  The plan asks for Latin only; one Java class (~120 lines) does that with nothing extra.
- **No `@capacitor/camera`.** It is MIT (and so is its `ioncamera-android` library), but it is
  not installed, brings Kotlin, Material and an image-editor activity, and the WebView file
  input already gives the system camera and picker with no permission. Fewer moving parts, the
  same code path on the web and in the app, and nothing new to keep at targetSdk 36.
- **Self-hosted tesseract files** instead of tesseract.js's jsDelivr default: offline after the
  first use, no third-party request, versions pinned by the lockfile.
- The Android APK must not carry the web OCR files: `ignoreAssetsPattern` gains `!<dir>ocr`.

## Tests

- `src/domain/ocr.test.ts`: joining, hyphenation (soft hyphen, compounds, word check),
  paragraphs from indent / gap / short line / blocks, loose leading, noise lines, quality,
  a property test that no word is lost or invented.
- `src/features/ocr/tesseractMap.test.ts`: tesseract output → `OcrResult`, monotonic progress.
- `src/features/ocr/OcrPage.test.tsx`: the flow with a fake recogniser (toggle, edit, low
  confidence, empty, errors, "Okuyucuda aç" saves an 'ocr' text and opens `/oku/:id`,
  "Kelimeleri çıkar" opens `/share`).
- `tests/e2e/ocr.spec.ts`: the real tesseract.js in the production build on a page drawn in the
  browser: ≥ 95 % words, hyphenation joined, no request leaves localhost (~6 s in CI Chromium).

## Deferred / risks

- Criterion 4 on a phone (10 real book photos, ≤ 3 s, ≥ 95 %) can only be measured on a
  device: add it to the real-device checklist. ML Kit is expected to meet it; the review screen
  is the safety net.
- `./gradlew assembleDebug` could not run in the agent's container (no Android SDK; Google's
  Maven is unreachable). The plugin was compiled with `javac` against signature stubs only; the
  first CI Android build is the real check. APK size grows by the Latin model (~4 MB per ABI).
- Multi-column pages rely on the engine's reading order; perspective correction, cropping and a
  live camera preview are not done.
- Using the lexicon as `isWord` for hyphenation (the domain function already accepts it).
